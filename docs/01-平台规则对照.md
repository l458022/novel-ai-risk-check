# 平台规则对照 —— 违规类型 → 可检测特征 映射

> 版本：v0.1
> 日期：2026-10-13
> 说明：本表把**平台官方公告的定性表述**翻译成**可计算的特征**。
> ⚠️ **平台从未公布量化阈值**，本表的映射是推断，不是平台标准。

---

## 一、三平台治理逻辑（先搞清打击目标不同）

| | 起点中文网 | 番茄小说 | 晋江文学城 |
|---|---|---|---|
| 商业模式 | 付费订阅 | 免费（广告） | 付费订阅 |
| 审核方式 | AI 检测 + 编辑复核 | **算法自动签约**（无人工） | AI 检测 + 编辑 |
| 打击核心 | **AI 替代核心内容产出** | **低质 / 量产 / 水文** | **创意型辅助越界** |
| 读者敏感点 | "花了钱还看 AI 写" | 逻辑要求低，要"爽点"密集 | 原创性 |
| 公开阈值 | 无 | 无 | 报道称 20%（未官方确认） |
| 处置梯度 | 限流→撤榜→屏蔽→下架 | 拒签→下架→封号 | 判定违规 |

**结论：三者打击目标不同，判据不能互相套用。**
本项目**优先对标起点**（重叙事逻辑与原创性），**其次番茄**（重水文与格式）。

## 二、起点中文网（优先对标）

### 2.1 官方表述

- **2025-04-21 公告**：反对"利用 AI 或其他自动化手段**替代真人完成核心内容产出**、
  干扰正常创作秩序"，加强对"**非真人自动化文字创作**"的规范管理。
- **处置梯度**：暂停推荐 → 撤下榜单 → 屏蔽作品 → 下架作品。
- **2025-08-18 实况**：集中处理一批"**AI 创作痕迹过重**"作品（含首页榜单热门书），
  实际处理为**撤榜 + 取消官方推荐流量**，未下架。
- **判定方式**（据受处理作者）：平台"通过 AI 检测全文，判断整本小说的 **AI 率**"。

### 2.2 一线可观测痕迹 → 检测特征

| 起点侧痕迹（作者/编辑/读者原话） | 可检测特征 | 归属模块 |
|---|---|---|
| 剧情起伏小，"一点活人味儿都没有" | 情绪/张力曲线平坦度 | `structure.js` |
| **标点过于规范，频繁使用破折号、顿号甚至单引号** | 破折号/顿号/单引号密度、标点多样性 | `novel_stylometry.js` |
| 反复使用固定描述方式 | 跨段 n-gram 重复率 | `consistency.js` |
| 加入与剧情无关的比喻和描写 | 描写/情节推进比 | `structure.js` |
| 大量无用环境描写、细节堆砌 | 环境描写占比、情节节点密度 | `structure.js` |
| 废话变多、情绪平淡 | 信息密度、情绪词分布 | `structure.js` |
| **提示词残留** | 模板串匹配 | `format.js` |
| 前后文脱节、情节错乱 | 人名/视角/时间线一致性 | `consistency.js` |
| 行文机械 | 句长波动（burstiness） | `novel_stylometry.js` |

> ⭐ **注意**：起点场景下"标点异常"是**第一梯队痕迹**，
> 与学术场景相反（学术场景 `punct` 已被证明是"人群伪信号"而降权）。
> **小说场景必须重新标定并上调权重。**

## 四、晋江文学城（参考，用于定位说明）

### 4.1 官方二分法（2025-02 试行公告）

| 类别 | 定义 | 是否允许 |
|---|---|---|
| **文字型辅助（校对级）** | 校对错别字、病句 | ✅ 允许 |
| **创意型辅助（要素级、粗纲级）** | 提供极简略、不涉具体情节的要素/粗纲 | ⚠️ 受限/需申报 |
| **写情节 / 描写场景 / 塑造人物** | 超出上述范围 | ❌ 违规 |

- 已引入 AI 检测助手，对投稿做 AI 内容检测；报道称 AI 含量 <20% 不计入统计。

### 4.2 对检测器的启示

⚠️ 晋江的标准**无法被自动检测**——工具无法知道作者"是否用 AI 拟了大纲"。
所以：
- 本工具**不判断"是否违规"**，只报告"文本层面的 AI 痕迹强度"；
- 报告里**引用晋江二分法**，帮助作者理解"哪些用法在平台眼里是安全的"。

| 检测模块 | 覆盖的平台违规类型 |

## 六、检测器的定位声明（必须出现在报告里）

> 本工具检测的是**文本层面的统计与结构特征**，属于《人工智能生成合成内容标识办法》
> 第六条第三款所称的"**其他生成合成痕迹**"，因此只能给出"**疑似**"判断。
>
> 1. 判据来源是**公开文献 + 行业经验**的启发式推断，**不是任何平台的官方标准**；
> 2. 本工具**不判断**"这篇是不是 AI 写的"，只报告**AI 痕迹强度**；
> 3. 本工具**不提供**"降低 AI 检测率 / 通过平台审核"的功能——
>    那会违反《标识办法》第十条（禁止为隐匿生成合成痕迹提供工具）；
> 4. 本工具的建议指向**提升文学质量**，而非规避检测。

## 七、修正说明：`stylometry.js` 的复用边界

⚠️ **原方案称"直接复用 stylometry.js"，此说法不准确，特此修正：**

`查重降AI项目/web/assets/stylometry.js` 是**英文专用**实现：

| 组件 | 英文实现 | 中文小说需要的 |
|---|---|---|
| `FUNCTION_WORDS` | 英文虚词表（the/of/and…） | **中文虚词表**（的/了/在/是/和…） |
| `words(text)` | `/[a-z][a-z'-]*/g` | **中文分词**（无空格，需 n-gram 或词典） |
| `sentences(text)` | 按 `.!?` 切分 | 按 `。！？……` 切分 |
| `countSyllables()` | 英文音节 | **不适用**（中文按字数） |
| `punctuationProfile()` | `; — ( ) :` | `—— …… "" 、 《》` 等中文标点 |
| `readability()` | Flesch（英文） | **不适用**，改为中文可读性近似 |

**可复用的部分（架构层，价值很大）：**
- `analyze(text, kb)` 的 **signals 数据结构**（key/label/value/aiScore/weight/evidence/note）
- **权重融合策略**：`strongKeys` + `strongVotes` 分档 + 封顶机制
- **短文本收缩**（按字数向中性低分收缩）
- **阈值外部化**（从 Learner 读调参）
- **每条信号带 `note` 说明局限** 的设计纪律

**结论**：**复用架构与判据设计纪律，特征函数全部中文化重写**。
